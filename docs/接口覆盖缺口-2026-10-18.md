# 整站接口覆盖缺口清单（2026-10-18）

## 这份文档是什么

2026-10-18 对官方 OpenAPI 与 App `core` 接口层做了一次逐路径、逐方法的对照，
把「网站有、App 还没有」的普通用户功能全部记录下来，供后续分批补齐。
BP-05 交付后，这份清单就是整站功能对照复盘的接口层结果。

- 本清单只管**接口与功能入口**，不代表 UI 细节已经逐页比对过；
- 管理面按 BP-05 合同不做，但仍列出，方便以后复查是否有遗漏的普通用户能力；
- 每完成一项，把对应勾选框改为 `[x]`，并补上版本号与 devlog 链接。

## 统计口径

- 规格来源：`research/reference/kun-galgame-forum/apps/api/openapi/kungal-v1.json`
  （官方 2026-10-17 版）
- 一个 **operation** = 一条路径 + 一个 HTTP 方法；同一路径的 GET/POST 算两个
- App 侧来源：`core/src/main/kotlin/com/kungal/core/api/*.kt` 里的路径字符串，
  变量段统一归一化成 `*` 后与规格比对
- 只比对「路径 + 方法」，不判断 UI 是否已经接线；UI 缺口单独标注

| 范围 | 路径 | operation |
|---|---:|---:|
| 官方全量 | 259 | 368 |
| 管理面 `/admin/*`（不做） | 24 | 41 |
| 普通用户面 | 235 | 327 |
| App 已覆盖 | 212 | 285 |
| **普通用户面缺口** | **23** | **42** |

按 operation 计算覆盖率：285 / 327 ≈ **87%**。

另有 OpenAPI 未收录、但 App 已经实现的接口：

- `/chat/*`：20 条路径、23 个接口（私信实时通道，网页走同域聊天服务）；
- `/auth/login`、`/auth/register`、`/auth/register/send-code`、`/oauth/authorize/consent`：
  4 条路径、9 个接口（原生登录/注册与 OAuth 同意）。

所以实际功能面比 87% 更全。完整对照命令见文末「复跑方法」。

## P0 · 投票管理与抽奖全流程（7 个缺口接口 + 1 个已有接口无 UI）

### 现状

App 已能：看投票、投票/撤票、看投票记录；看抽奖、参与/退出、看参与名单、中奖名单、
中奖者揭示兑换码。

App 缺的是**作者侧**：创建投票、编辑/删除投票、创建抽奖、编辑/开奖/取消/删除抽奖、
管理实物奖履约。这是目前唯一一整套「网站能做、App 没有入口」的用户功能。

网页入口：话题详情的小程序区（`components/topic/poll/*`、`components/topic/lottery/*`），
仅话题作者/管理员可见创建与编辑；话题创建时也可以勾选小程序。

### 接口明细

| # | 方法 | 路径 | 说明 | core 现状 |
|---|---|---|---|---|
| 1 | POST | `/topics/{topic_id}/polls` | 创建投票（需 `Idempotency-Key`） | `TopicApi.createPoll` 已有，App 无 UI |
| 2 | PATCH | `/polls/{poll_id}` | 编辑投票 | 缺 |
| 3 | DELETE | `/polls/{poll_id}` | 删除投票（204） | 缺 |
| 4 | POST | `/topics/{topic_id}/lotteries` | 创建抽奖（需 `Idempotency-Key`） | 缺 |
| 5 | PATCH | `/lotteries/{lottery_id}` | 编辑；`state=drawn` 立即开奖，`state=cancelled` 取消 | 缺 |
| 6 | DELETE | `/lotteries/{lottery_id}` | 删除抽奖（204），未开奖奖池退回 | 缺 |
| 7 | GET | `/lotteries/{lottery_id}/winners/{winner_id}` | 单个中奖记录 | 缺 |
| 8 | PATCH | `/lotteries/{lottery_id}/winners/{winner_id}` | 履约状态 | 缺 |

### 投票字段

创建体（`POST /topics/{topic_id}/polls`）：

- 必填：`title`、`options[]`（每项 `{text}`）、`choice_type`（`single|multiple`）、
  `result_visibility`（`always|after_vote|after_deadline`）
- 可选：`description`、`closes_at`、`min_choice`、`max_choice`、`is_anonymous`、
  `can_change_vote`
- 模型 `PollCreate` / `PollOptionCreate` 已存在，可直接复用

编辑体（`PATCH`）与创建体基本相同，但选项通过 `option_changes` 增删改：

```json
{
  "option_changes": {
    "add": [{ "text": "新选项" }],
    "remove": ["option_id"],
    "update": [{ "option_id": "option_id", "text": "改后的文本" }]
  }
}
```

只发变化字段；网页编辑器支持改标题、描述、截止时间、可见性、是否匿名、可否改票。

### 抽奖字段

创建体（`POST /topics/{topic_id}/lotteries`）：

- 必填：`title`、`entry_mode`（`signup|reply|floor`）、`draw_mode`
  （`deadline|manual|threshold`）、`prizes[]`
- 可选：`description`、`closes_at`、`floor_rule`（`entry_mode=floor` 时）、
  `draw_threshold`（`draw_mode=threshold` 时）、`min_account_age_days`、
  `min_moemoepoint`、`is_entry_list_public`
- 奖品 `prizes[]`：`title`、`slot_count`、`delivery`（`code|offline|point`）、
  `description`、`image_hashes`、`adult_image_hashes`；
  - `delivery=code`：`codes[]`（兑换码列表）
  - `delivery=point`：`point_mode`、`point_amount`（萌萌点奖池）
- 编辑体（`PATCH`）同上，另有 `state=drawn|cancelled`；
  网页只在「可以开奖/可以取消」时显示对应按钮
- 履约体：`{ "fulfillment": "pending|shipped|received|forfeited" }`

`Lottery` / `LotteryPrize` / `LotteryWinner` / `LotteryViewer` 模型已存在，
`viewer` 里已有 `can_edit / can_delete / can_draw / can_cancel / can_manage_fulfillment`，
UI 可直接按这些标志决定按钮可见性。

### UI 接线建议

- 话题详情「投票」区：作者可见「新建投票」；每张投票卡片提供「编辑 / 删除」。
- 话题详情「抽奖」区：作者可见「新建抽奖」；卡片提供「编辑 / 立即开奖 / 取消 / 删除」；
  开奖后中奖列表每条提供履约状态切换（仅 `can_manage_fulfillment`）。
- 投票表单：标题、描述、单选/多选、选项增删、截止时间、结果可见性、匿名、可否改票。
- 抽奖表单：标题、描述、参与方式、开奖方式、截止时间、门槛（账号天数/萌萌点）、
  参与名单公开、奖品列表（名称、名额、发放方式、兑换码/萌萌点、图片）。
- 删除/开奖/取消都要二次确认，文案与网页一致（删除不可恢复、开奖不可撤销）。
- 创建请求带 `Idempotency-Key`；编辑不带（与网页一致）。

### 风险与验证门

- 抽奖涉及**萌萌点托管与实物履约**，属于高风险真实写操作：
  - 离线只验证请求构造与 JSON 字段；
  - 真实创建/开奖/删除必须由驾驶员明确同意后，用测试话题验证；
  - 不在自动测试里调用真实接口。
- 图片上传复用现有 `/images` 与奖品格；`adult_image_hashes` 沿用内容分级设置。
- `floor_rule`、`draw_threshold` 的客户端校验规则以网页为准，先在表单层做同样限制。

### 完成条件

- 8 个接口进 `TopicApi`，带夹具单测（请求方法/路径/幂等键/请求体）；
- 投票与抽奖的作者入口在话题详情可见，非作者不可见；
- `assembleDebug` + core/app 单测 + 装机；
- 真实写操作由驾驶员验证后，才在本文档打勾。

## P1 · 用户主页「评论 / 点赞评论」（1 个接口）

### 现状

网页用户主页的 Galgame 区有 5 个子页：已发布、贡献的、已点赞、评论、点赞评论。
App 的 Galgame 标签目前只有「发布 / 贡献 / 点赞」三种关系，后两个子页缺失。

### 接口

`GET /users/{user_id}/wall-comments`

| 参数 | 必填 | 说明 |
|---|---|---|
| `relation` | 是 | `authored`（评论）或 `liked`（点赞评论） |
| `subject_type` | 否 | 网页固定传 `galgame`；省略表示全部墙 |
| `cursor` / `limit` | 否 | 游标分页，默认 24，上限 100 |

返回 `{ items: WallComment[], next_cursor }`。App 已有 `WallComment`、`WallCommentList`、
`ContentDocument` 渲染器和墙评论卡片，模型可直接复用。

网页卡片显示：评论正文、`评论于 Galgame #{subject_id}`、日期；
点按跳 `/galgame/{subject_id}?comment={comment_id}`。

### UI 接线建议

- `UserTab.GALGAME` 增加「评论 / 点赞评论」两个筛选（与现有发布/贡献/点赞并列）；
- 或按网页拆成子页；考虑标签行长度，优先用现有 `FilterChips` 复用；
- 卡片点按走原生作品页并定位评论（若作品页支持 `?comment=` 定位则接上，
  否则先打开作品页）。

### 完成条件

- core 方法 + 夹具单测；app 两个关系页；匿名可读；构建/单测/装机。

## P2 · 标签多选、表情包、@提及（3 个接口）

### P2.1 标签多选筛选

`GET /tagged-works`

| 参数 | 必填 | 说明 |
|---|---|---|
| `tag_ids` | 是 | 逗号分隔，1–10 个；返回同时带全部标签的作品 |
| `page` / `limit` | 否 | 页码分页，默认 24 |
| `include_nsfw` | 否 | 默认 false |
| `include_all_original_languages` | 否 | 默认 false（原语言门禁） |
| `exclude_tag_ids` / `exclude_tag_trees` | 否 | 屏蔽标签 |

网页标签页可以勾多个标签联合筛选；App 目前只有单标签详情
（`EntityApi.tagWorks`）。现有作品卡片与分页可直接复用。

### P2.2 表情包选择器

`GET /sticker-packs`

- 返回 `{ items: [{ id, display_name, stickers: [...] }], next_cursor }`
- 支持 `If-None-Match` / ETag，可缓存整包
- 网页编辑器与私信输入框共用同一份清单，懒加载一次
- App 已能渲染表情节点（`ContentRenderer` 的 `isSticker` 分支），缺的是**插入入口**：
  编辑器工具栏表情面板、私信输入框表情面板

### P2.3 @提及与用户解析

`GET /users`

| 参数 | 说明 |
|---|---|
| `q` 或 `ids` | 二选一；`ids` 逗号分隔，1–100 个 |
| `limit` | 仅 `q` 生效，1–20，默认 8 |

- 返回 `{ items: UserRef[], missing: [] }`，比 `/search/users` 更轻
- 网页用途：编辑器 @提及自动补全、话题权限用户选择（`AccessUserPicker`）
- App 话题编辑器占位文案已写「@提及」，但没有自动补全；接入后可复用用户行样式

### 完成条件

- 标签多选：标签详情页支持勾选多个标签并联合筛选；
- 表情包：编辑器与私信都能打开选择器并插入；
- @提及：输入 `@` 后按关键字联想用户，选中插入用户名；
- 各自带 core 单测与基本 UI 验证。

## P3 · 小项（4 个接口）

### P3.1 关注分组展开

`GET /activity-groups/{group_id}/items`

- 参数：`cursor`、`limit`（≤50，默认 20）、`include_nsfw`
- 现状：App 的关注流分组只显示分组自带的少量条目，并提示「共 N 条」，
  不能展开；网页可点「加载更多」把该组全部条目拉出来
- 接法：分组卡片底部「查看全部 / 加载更多」，组内游标分页

### P3.2 题库收藏态批量查询

`GET /me/quiz-states?quiz_ids=1,2,...`

- 1–100 个 id，返回 `{ items: [{ quiz_id, has_favorited }], missing: [] }`
- 网页用于动态卡片上的题库收藏心形；App 的动态题库卡片目前没有收藏状态
- 若后续在动态卡片加收藏按钮，需要此接口做批量初始化

### P3.3 旧收藏夹链接兼容

`GET /collection-aliases/{alias_id}`

- 输入旧论坛收藏夹 id，返回 `{ alias_id, collection_id }`
- 用途：老链接 `/collection/{旧id}` 跳转到新收藏夹；网页由服务端中间件处理
- App 的 `openInternalPath` 若遇到旧 id 打不开，可先用它解析

### P3.4 旧会社 id 兼容

`GET /wiki-company-redirects/{wiki_company_id}`

- 输入旧 wiki 会社 id，返回 `{ wiki_company_id, company_id }`
- 用途：旧会社链接跳转到资料库会社；同样由网页中间件处理
- 属于兼容性小项，优先级最低

## 明确不补的 27 个接口

### 站务 / 管理 / 审核面（12 个）

按 BP-05 合同，App 不开放管理面：

- 待办：`POST /todos`、`GET|PATCH|DELETE /todos/{todo_id}`
- 更新日志：`POST /update-logs`、`GET|PATCH|DELETE /update-logs/{update_log_id}`
- 作品投稿审核队列：`GET /work-submissions`（网页 `/admin/submissions`）
- 审阅记录：`GET /me/work-submission-reviews`（网页 `/edit/galgame/audited`，
  审核者入口）
- 资源发布封禁：`PUT|DELETE /works/{work_id}/resource-publish-ban`

> 说明：App 自己的作品投稿（我的投稿、创建、编辑、删除）已经实现，
> 这里缺的只是审核与站务写入。

### 元数据（3 个）

- `GET /problems`、`GET /problems/reasons`：错误码字典，客户端不需要在线查询
- `GET /app/version`：官方 App 版本门禁；本项目是第三方客户端，不冒用官方身份

### 旧接口 / 网页已不调用（7 个）

- `GET /me/conversations`、`GET /me/conversations/{user_id}`、
  `GET|POST /me/conversations/{user_id}/messages`、
  `GET|PATCH /me/conversations/{user_id}/messages/{message_id}`、
  `PUT /me/conversations/{user_id}/read-marker`

网页私信已全部走 `/chat/*`（App 也已实现 23 个接口），这组是旧会话接口，
官方前端没有调用点。

### 已有等价实现或网页不用（5 个）

- `PUT /me/notification-preferences`：整体替换静音类型；
  App 用单类型接口（`muted-types/{type}`）更安全，不会抹掉客户端不认识的类型
- `GET /me/notifications/{notification_id}`：单条通知；网页与 App 都只用列表
- `GET /wall-comments/{wall_comment_id}`：单条留言；列表已带完整内容
- `GET /works/{work_id}/covers/{cover_id}`：单张封面；作品详情已带封面
- `GET /work-suggestions`：题库出题的作品联想；App 用 `/search/works` 等价替代

## 复跑方法

在仓库根目录执行（只读，不发网络请求）：

```bash
python - <<'PY'
import json,re,glob,collections
spec=json.load(open('research/reference/kun-galgame-forum/apps/api/openapi/kungal-v1.json',encoding='utf-8'))
def norm(p):
    p=re.sub(r'\{[^}]+\}','*',p); p=re.sub(r'\$[A-Za-z0-9_]+','*',p); return re.sub(r'/+$','',p)
impl=collections.defaultdict(set)
mm={'get':'GET','getWithResponse':'GET','postJson':'POST','postJsonWithResponse':'POST',
    'postNoBody':'POST','postNoBodyJson':'POST','postJsonNoContent':'POST','postMultipart':'POST',
    'put':'PUT','putJson':'PUT','putNoBody':'PUT','putMultipart':'PUT',
    'patchJson':'PATCH','patchJsonWithResponse':'PATCH','delete':'DELETE','deleteNoBody':'DELETE'}
for f in glob.glob('core/src/main/kotlin/com/kungal/core/api/*.kt'):
    s=open(f,encoding='utf-8').read()
    for m in re.finditer(r'client\.([A-Za-z]+)\s*\(\s*(?:path\s*=\s*)?"(/[^"\n]*)"',s):
        if m.group(1) in mm: impl[norm(m.group(2))].add(mm[m.group(1)])
    for m in re.finditer(r'val\s+path\s*=\s*"(/[^"\n]*)"',s):
        for m2 in re.finditer(r'client\.([A-Za-z]+)\s*\(\s*path\b',s):
            if m2.group(1) in mm: impl[norm(m.group(1))].add(mm[m2.group(1)])
for p,item in sorted(spec['paths'].items()):
    ops={k.upper():v for k,v in item.items() if k.lower() in ('get','post','put','patch','delete')}
    miss=[m for m in ops if m not in impl.get(norm(p),set())]
    if miss: print(p, ','.join(miss))
PY
```

注意：

- 该脚本只认 `core` 里写死的路径字符串；如果以后出现非常规拼接，需要人工核对；
- 覆盖 ≠ UI 完成：`POST /topics/{topic_id}/polls` 就是「core 有、UI 没有」的例子；
- 官方 OpenAPI 更新后重跑，新增缺口直接补进本文件。
