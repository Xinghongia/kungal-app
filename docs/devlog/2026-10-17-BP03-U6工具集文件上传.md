# 2026-10-17 · BP-03 U6 工具集文件上传（0.5.5）

## 交付内容

工具集「对象存储 (S3)」资源现在可以真正上传压缩包，不再只是占位提示。

- **core**：`KungalClient.putExternalStream` —— 预签名 S3 地址的流式 PUT：
  - 不携带站点 cookie 与 App UA（S3 直传不需要，也不应带会话）；
  - 64KB 缓冲流式读取，支持进度回调，不把 2GB 文件读进内存；
  - 可取消（暴露 OkHttp `Call`），返回响应 `ETag`；
  - 上传专用客户端关闭写超时，避免慢网络下大文件被 10 秒写超时打断。
- **app**：
  - 上传规则：仅 `.7z/.zip/.rar`、单文件 ≤2GB、分片阈值 50MB、
    今日额度 = 100MB + 萌萌点×1MB、单文件上限 = min(max(100MB, 萌萌点/10 MB), 2GB)、
    `toolset.upload_bypass` 权限账号不受每日用量限制；与服务端 `uploads.go` /
    网页 `config/upload.ts` 对齐。
  - 上传流程：创建会话 → 小文件单次 PUT / 大文件按服务端 `part_size` 分片 PUT
    （收集每片 ETag）→ PATCH 完成；分片续传只补传服务端列出的缺失片，
    合并服务端已传分片的 ETag 后完成。
  - 断点记录存 DataStore（`toolset_uploads`），记录含 SAF Uri、文件名、大小、
    进度与完成状态；选择文件时申请持久读权限，应用重启后可直接续传。
    已完成的上传单独列出，可直接「使用」发布；发布成功或 artifact 失效后移除记录。
  - 上传界面：今日已用/剩余额度进度、单文件上限、选择压缩包、单次/分片提示、
    实时进度、取消上传（同时中止服务端会话）、未完成上传续传/彻底删除、
    已完成文件复用。
  - 发布 file 资源时提交 `toolset_resource_type=file` + `artifact_id` +
    解压码/备注；服务端返回 artifact 失效（`UNKNOWN_REFERENCE`）或
    已发布（`ALREADY_EXISTS`）时如实提示并清掉该上传结果，要求重新上传。

## 契约依据

- `POST /toolsets/{id}/uploads` → `ToolsetUpload`（`is_multipart`、`upload_url`、
  `part_size`、`part_urls`、`uploaded_parts`、`expires_at`）。
- 小文件：`PUT upload_url` 后 `PATCH .../uploads/{id}` `{"state":"completed"}`。
- 大文件：逐片 `PUT part_urls[i].url`，从响应头取 `ETag`，完成后
  `PATCH` 带 `parts:[{part_number,etag}]`。
- 续传：`GET /toolsets/{id}/uploads/{id}` 返回已传分片和缺失分片地址。
- 中止：`DELETE /toolsets/{id}/uploads/{id}`（已完成会话不可中止）。
- 规则来源：服务端 `internal/toolset/apiv1/uploads.go` / `helpers.go`、
  网页 `config/upload.ts`（只读参考，代码为自行实现）。

## 未验证与已知边界

- **真实上传未在驾驶员账号执行**：按约定写操作需驾驶员同意；本轮未向站点上传
  任何文件。真机验证请由驾驶员用自己的压缩包走一遍（建议先传一个几 MB 的小文件）。
- 分片上传只在 MockWebServer 沙盒验证了 PUT/ETag/PATCH 机制，未与真实 S3 联调；
  真实分片（>50MB）的上传速度、预签名过期与续传需真机验证。
- 单文件上传失败后记录里的进度为 0（服务端会话可重传整文件）；分片进度按片保存，
  不是逐字节保存。
- 上传没有前台服务/通知：离开工具集详情页会取消当前请求，断点记录保留，
  下次进入可续传。锁屏或切后台是否能持续取决于系统对进程的处理。
- 部分文件管理器不授予持久读权限时，应用重启后需重新选择同一个文件；
  续传会校验文件名与大小，不一致会要求重新选择。
- `artifact` 已发布过时服务端返回 `ALREADY_EXISTS`，App 会移除本地记录；
  若同一个文件确实还要再发布，需要重新上传。
