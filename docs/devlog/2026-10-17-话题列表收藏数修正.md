# 2026-10-17 · 话题列表收藏数修正（0.7.5）

## 背景

驾驶员对比网站发现：话题列表卡片右下角心形数字与网页不一致
（例子：话题 3938 网页显示收藏 134，App 显示 111）。

## 根因

- App 的心形图标用的是 `like_count`（点赞数 111）。
- 网页首页话题卡片的**心形是收藏数**，取自 `topic_digest.favorite_count`（134）。
- `GET /topics` 的话题摘要**不返回** `favorite_count`（OpenAPI `TopicSummary`
  只有 `like_count / reply_count / comment_count / view_count`）；只有
  `GET /topics/{id}` 的完整 `Topic` 和 `GET /activities` 的 `topic_digest` 才有。
  网页正是从 `/activities?activity_types=topic_creation&sort=bumped_desc` 取这份数字。

## 改动

- core：新增 `ActivityApi.activities`（游标 / limit / activity_types / sort /
  topic_sections / include_nsfw）与 `FeedActivity`、`TopicDigest` 模型；
  1 项新单测（动态解析收藏数 + 请求参数）。
- app：话题列表在每页加载后，按 bumped 顺序遍历一次话题动态，把
  `topic.id → favorite_count` 缓存起来（最多向前补 6 页、100 条/页），
  卡片心形显示该收藏数；翻页、换排序不重复请求，切换 NSFW 姿态时清空缓存重取。
- 气泡数字改为「回复 + 评论」，与网页卡片一致（此前只显示回复数）。
- 心形图标恢复为收藏图标并恢复常显（上一版误改为点赞图标且为 0 隐藏，已撤回）。

## 未验证与已知边界

- 收藏数依赖 `/activities` 的 `topic_creation` 流是否覆盖到该话题：极老、被隐藏
  或不在动态流里的话题可能取不到收藏数，此时按 0 显示（网页同样取不到时也不显示收藏数）；
- 每次列表加载会额外发起 1 次（最多 6 次）动态请求，仅在缓存缺项时触发；
- 未做「下拉刷新后收藏数也刷新」的强制刷新，刷新列表本身会补齐新出现的话题。
