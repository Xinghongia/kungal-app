## 2. core：网络与接口层

### 2.1 KungalClient

- base URL：`https://www.kungal.com/api/v1`（`KungalClient.DEFAULT_BASE_URL`）。
- 每个请求带 `Accept: application/json`、`User-Agent: kungal-app/<version> (Android)`；
  有会话时带 `Cookie: kungal_session=...`。
- 统一入口（都挂 `Dispatchers.IO`）：
  | 方法 | 用途 |
  |---|---|
  | `get` | 读接口 |
  | `postJson` / `postJsonNoContent` | 带 JSON 体的写接口（可带 `Idempotency-Key`） |
  | `postNoBody` / `postNoBodyJson` | 无请求体的 POST（浏览计数、签到、兑换码） |
  | `put` / `putJson` / `patchJson` | 无体 PUT、JSON PUT/PATCH |
  | `delete` / `deleteNoBody` | 需要/不需要响应体的 DELETE |
  | `postMultipart` / `putMultipart` | 文件上传（字段名固定 `file`） |
  | `downloadBytes` | 下载图片等二进制 |
- `url(path, query)`：query 里 `Iterable` 会展开成重复键（如
  `/users/{id}/work-records?state=doing&state=wish`），null 跳过。
- 非 2xx 一律解析 problem+json 并抛 `KungalApiException`
  （`httpStatus`、`problem?.code`、`retryAfterSeconds`）；
  `requiresLogin`（401/205）与 `isRateLimited`（429）供界面分支。
- 响应解析失败也抛 `KungalApiException`（HTTP 状态保留）。

### 2.2 JSON 约定

`KungalJson`（core/KungalJson.kt）：

- `ignoreUnknownKeys = true`：站点随时加字段，不能解析崩。
- `explicitNulls = false`：缺省与 null 等价。
- `encodeDefaults = true`：请求体里**有默认值的必填字段**必须发出去
  （如 `access_scope`、`choice_type`、`is_sign_in_required`）。

模型建议：所有可缺省字段给 Kotlin 默认值；枚举类字段用 `String` + 界面映射，
避免站点加枚举值时崩溃（如 reaction token、play_state）。

### 2.3 分页形状

| 形状 | 模型 | 用途 |
|---|---|---|
| `{object:"list", items[], next_cursor}` | `PageList<T>` | 游标分页（话题/回复/通知/私信/商店…） |
| `{object:"list", items[], total, total_relation}` | `PagedList<T>` | 页码分页（用户内容/评分/题库/工具集…） |
| 特例 | `WorkRecordPage`、`PlaytimePage` | 游标 + 附加字段（state_counts / 汇总） |

页码分页的「是否还有下一页」统一按**本页条数 < pageSize** 判断（站点 `total_relation`
可能是 `gte`，total 不保证精确）。

### 2.5 会话

- `SessionHolder` 持有 `kungal_session` cookie 字符串；`KungalClient` 每次请求读取。
- `KungalApp` 启动时 `restoreSession()` 从 `SessionStore`（DataStore）恢复。
- 网页登录走账号中心 OAuth：App 生成 PKCE 打开 `/oauth/authorize`，WebView 拦下
  `/auth/callback` 后用 `AccountAuthApi.exchangeAuthorizationCode` 换 `kungal_session`；
  成功后调用 `app.onLoggedIn(cookie)` 持久化并注入。原生登录复用同一套
  `/auth/login` → `/oauth/authorize/consent` → `/api/auth/oauth/callback`。
- 任何接口返回 401/205 → `KungalApiException.requiresLogin` → 界面引导重新登录；
  「我的」页会顺带清理失效会话。
- 登出只清本地（`app.logout()`），不调用站点登出接口。
- 私信实时：登录后 `ChatRealtimeHub` 用 `/chat/realtime-token` 连接 Centrifugo，
  登出断开；token 约 15 分钟，到期前主动换新连接。`ChatRealtimeClient`（core）只负责
  Centrifugo JSON 协议；重连、`/chat/updates` 补齐、角标刷新都在 Hub。

## 3. app：界面层

### 3.1 依赖装配（KungalApp）

- `client`、各 `*Api`、`sessionStore`、`settingsStore` 在 `onCreate` 建好；
  新接口类在这里挂 `lateinit var` + 初始化。
- `chatRealtime`（`ChatRealtimeHub`）：私信实时通道，`session` 变化时启动/停止；
  暴露 `pushes`、`syncPages`、`connected` 供界面订阅。
- `rankingApi`：排行榜三个接口。
- `session: StateFlow<Session?>`、`isLoggedIn`：登录态。
- `currentUserId: StateFlow<String?>`：由 `/me/account` 回填，用于「自己的内容」判断。
- `accountRule`（`accountRevision`）：资料保存后 `notifyAccountChanged()`，
  「我的」页与个人主页监听后刷新。
- `contentStance: StateFlow<NsfwDisplayMode>`：登录跟账号（`/me/account` 的
  `content_stance`），未登录用本机设置。
- `stickerPacks()`：官方表情包整包缓存（`Mutex` 保护，一次进程只请求一次），
  编辑器与私信共用；`StickerApi` 本身不做 ETag 条件请求。

### 3.2 导航（AppNav.kt）

- 一级（底部导航）：`tab/topic`、`tab/galgame`、`tab/discover`、`tab/messages`、`tab/profile`。
- 二级（压栈、隐藏底栏）：`topic/{id}`、`user/{id}`、`user/{id}/follow`、
  `profile/settings`、`settings`、`editor`、`drafts`、`publish`、`search`、
  `subscriptions`、`following`、`login`、`soon`、`points`、`shop`、`creator`、
  `messages/notifications`、`messages/notifications/muted`、
  `messages/notifications/preferences`、`messages/walls`、
  `messages/chat`、`messages/chat/room`、`messages/chat/settings`、
  `ranking`、`settings/preferences`；以及 Galgame 域（资料库/词条/实体/评分/
  资源/题库/月历/投稿/网站）、情报、文档、友链、子站、动态、更新、待办、
  关于三页等（完整清单见 `Routes` 常量）。
- 站内路径统一走 `openInternalPath` / `openUrlOrPath` 分发；能原生打开的路径
  一律进原生页，未知路径才交给浏览器。
- 新增页面：在 `Routes` 加常量与构造函数 → `NavHost` 里 `composable` →
  调用方用 `nav.navigate(...)`。
- 切换底部 tab 用 `switchTab`（保存/恢复各 tab 返回栈，避免堆叠）。

### 3.3 状态管理约定

- 每屏一个 `ViewModel`（`androidx.lifecycle.ViewModel`），暴露不可变
  `StateFlow<State>`；UI 用 `collectAsState()`。
- 网络调用一律 `viewModelScope.launch { runCatching { ... }.onSuccess/.onFailure }`；
  错误文案走 `friendlyError(e)`（话题包，全 App 复用）：
  登录过期 / 限流 / 网络失败 / 服务端 detail。
- 写操作要有 `busy` 标志防连点；失败如实提示，不吞错。
- 需要「数据变化后刷新」时用 `LaunchedEffect(key)`（session、accountRevision、
  筛选条件等）。

### 3.5 正文与图片

- 服务端下发 `ContentDocument` 节点树；`ContentRenderer` 渲染段落/标题/列表/代码/表格/
  spoiler/图片等，未知节点跳过。整棵树包在 `SelectionContainer` 里，长按可选中文字复制；
  链接与剧透的点击不受影响。所在页面在空白区域点击时递增
  `LocalTextSelectionClearSignal`，正文/评论会调用 `SelectionState.clear()` 取消选中。
- 头像：`AvatarImage(url, modifier, seed)`；`seed` 传用户名。没有上传头像的账号与网页一致，
  由 `AvatarPool`（64 张默认头像池 + `h*31+charCode` 取模）挑图；池启动时尝试刷新，
  失败沿用内置快照（版本 `cd41af02cb0050ea`）。新增头像位置时记得传 `seed`。
- 图片走内容寻址 CDN，Coil 加载；`KungalApp` 注册了 `AnimatedImageDecoder`/`GifDecoder`
  （站点表情是动态 WebP）。
- 正文图片点击由 `LocalImageClicker` 提供，打开 `ImageViewer`
  （缩放、拖动、保存、复制链接、分享）。

### 3.6 表情包、@提及、旧 id 兼容与话题小程序

- 表情包：`StickerPickerDialog` 通过 `app.stickerPacks()` 读取官方整包并缓存；
  插入正文用 `stickerMarkdown()`（320 变体、`![名称](url)`），私信发送则调用
  `ChatViewModel.sendSticker()`，把 `image_hash` 作为图片消息提交。
- @提及：话题编辑器监听正文末尾的 `@关键词`（300ms 防抖），调用
  `UserApi.resolveUsers(q, limit)` 显示候选；点选后用 `@昵称 ` 替换正在输入的一段。
  仅登录时请求。
- 旧 id 兼容：收藏夹 / 会社详情先按新 id 请求，404 时分别调用
  `CollectionApi.alias`、`GalgameEntityApi.companyRedirect` 解析后再加载；
  后续列表与写操作都使用解析后的 id。
- 题库批量状态：动态每页用 `QuizApi.states(ids)` 一次取回收藏态，
  卡片上的心形乐观更新、失败回滚。
- 话题小程序：话题详情底部「话题小程序」面板只对作者或 `viewer.canEdit` 可见；
  `PollFormDialog` / `LotteryFormDialog` 负责创建与编辑，卡片上的编辑 / 删除 /
  开奖 / 取消按 `viewer` 标志显示。投票 PATCH 的 `option_changes` 只发增删改；
  `closes_at` 用 `JsonNull` 明确清除。抽奖的截止时间只选到日，提交时按本地
  23:59:59 转成 20 位 UTC；已有人参与后参与方式、楼层规则与奖项锁定。
  奖品图片解析为 `LotteryPrizeImage`（hash + 嵌套 image + 成人标记），
  `include_nsfw` 跟随内容姿态，隐藏不渲染、模糊打码。
- 改名页展示的 `rename_cost` 是**价格**，不是余额；余额来自 `/me` 的
  `moemoepoint`，两者必须分开显示，改名成功后重新拉 `/me`。

### 3.7 主题、设置与 NSFW

- 主题：Material 3 + 6 套预设 + 动态取色 + 深浅/纯黑；`SettingsStore` 持久化。
- NSFW 三态（隐藏/模糊/显示）：登录写 `/me/nsfw-display`，未登录存本机；
  列表按 `allowsNsfw` 传 `include_nsfw`，模糊模式封面打码。
- 语言暂跟随系统（尚无独立 i18n）。

## 4. 典型数据流

**读列表**：`Screen` → `ViewModel.refresh()` → `Api.list(cursor/page)` →
更新 `StateFlow` → Compose 重组；触底调用 `loadMore()`。

**写操作**：点击 → 确认弹窗（扣点/危险操作必须确认）→ `ViewModel.doXxx()` →
`suspend` API（幂等键）→ 成功后刷新或本地更新 → Snackbar 提示；
失败展示服务端 detail。

**跨页刷新**：例如资料保存后 `app.notifyAccountChanged()`，个人主页/我的页监听
`accountRevision` 重新拉取。

## 6. 新增一个域的步骤

1. 从 OpenAPI（`research/reference/.../kungal-v1.json`）和网站页面确认接口、字段、权限；
   需要时用只读请求抓真实样本。
2. core：`model/Xxx.kt` → `api/XxxApi.kt` → `UserApiTest`/`XxxApiTest` 单测。
3. `KungalApp` 装配新 `Api`。
4. app：`ViewModel`（State + 动作）→ Screen → `AppNav` 路由 → 入口。
5. 构建 + 单测 → 装机 → 更新 `docs/devlog/`、`NEXT.md`、蓝图状态。
6. 涉及真实写入的入口默认只实现，不替驾驶员执行；由驾驶员验证。

## 7. 已知约束与坑

- **写操作授权**：不得在驾驶员账号上擅自发帖/回复/签到/下单/改资料；需要时先问。
- **AGPL 边界**：官方源码只读参考，不复制任何代码；客户端保持 MIT。
  例外说明：空状态与下拉刷新插图（`res/drawable-nodpi/kun_empty.webp`、
  `kun_loading.webp`）取自官方 KunUI（`@kungal/ui-vue` 2.57.1，AGPL-3.0-only），
  仅作界面装饰；对外发布时需在 README/NOTICE 标注来源与许可，或向站长确认授权。
- **不要批量抓取**：探测样本按需少量请求。
- `Content-Type`：JSON 请求统一 `application/json; charset=utf-8`；
  multipart 字段名必须是 `file`。
- 时间：接口为 ISO-8601 UTC；界面用 `fullDateTime`（精确到秒）或 `relativeTime`。
- 用户内容列表的 `relation` 是**必填**参数；话题 `hidden` 仅本人或有权限者可见。
- 游戏库接口的状态参数是重复键数组，不是逗号分隔。
- 作品/评分/题库/工具集/收藏夹详情页在 BP-02/03/05 交付前跳网页，
  列表数据已是真实接口。
- 商店/签到/改名等扣点操作必须显示价格并二次确认。
- 通知列表进入/翻页后会把已加载的未读通知标为已读（与网页一致）；
  通知里的站内路径只有 `/topic/{id}`、`/user/{id}` 进 App，其余跳网页。
- 关注墙可以列出与取消关注；新增关注仍需网页详情页（客户端详情页未交付）。
- 带 `header` 的分页列表顶部不要留 `contentPadding`，否则切换标签时头部会上下跳；
  筛选 `key` 变化时 `PagedListContent` 会自动滚回顶部。
- 列表页的下拉刷新统一用 `KungalPullToRefresh`（官方 KunUI Loading 插图），
  不要直接用 Material3 默认指示器；下拉期间保留旧列表，避免同时出现第二个加载占位。
- 私信（U4）走 `/api/v1/chat/*`：会话按 `folder=inbox|requests|archive` 拉取；
  消息发送用 `client_message_id`（UUID）去重；实时通道/表情/置顶属于 U5，
  当前会话页只有手动刷新。消息富文本只按纯文本显示，不解析 `entities`。
- 私信图片：优先用消息里的 `media.url`，缺省时按 `/{hash0:2}/{hash2:4}/{hash}.webp`
  拼内容寻址 CDN；上传走 `POST /chat/images`（multipart，字段 `file`）。
- 私信实时（U5）：Centrifugo JSON 协议（换行分隔的 JSON 帧，`push.pub.data` 就是
  `ChatPush`）；服务端空帧心跳要回空帧。token 约 15 分钟，Hub 在到期前重连；
  重连先订阅推送、再按 `/chat/updates?after=<last_update_seq>` 补齐；推送序号跳号时
  等 500ms 再整段补齐。断线时界面明确显示「实时通道未连接 · 可手动刷新」。
- 表情回应是单选：再点同一种即取消；取消请求必须显式发 `{"reaction":null}`
  （`KungalJson` 的 `explicitNulls=false` 会省略 null 字段）。
- 消息置顶与会话置顶是两回事：消息置顶走 `/chat/conversations/{id}/pins/{seq}`，
  会话置顶走 `PATCH /chat/conversations/{id}/me {pinned:true}`。
- 云端偏好写回只改认识的键（`show_platform`…`show_kohaku`），`feed_tabs` 等未知字段
  原样保留；带 `If-Match: "<version>"`，412 时拉最新文档合并后重试一次。
- 排行榜是 top-N（默认 50 条），不做无限翻页；用户/话题条目进 App，Galgame 作品跳网页。
- 本人主页背景来自 `/me/shop` 的 `profile_background` 装备槽（`this_site` 优先于
  `everywhere`），其他用户的主页背景网页本身也不下发，App 不伪造。
- 界面轻提示统一用 `AppMessages.show(...)`（根部 `AppMessageHost` 渲染主题化提示），
  不要再用系统 `Toast`。页面已有自己的 `SnackbarHostState` 时，`snackbarHost` 槽位
  必须用 `KungalSnackbarHost(...)`，不要用 Material 默认 `SnackbarHost`（默认是深色横条）。
  Dialog 内的提示（如图片查看器）不会被根部提示覆盖，需要在 Dialog 内部自行渲染。
- 资料设置隐私开关是乐观更新：点击立即切换且保持可点，300ms 防抖只提交最后一次；
  保存期间不要设 `enabled=false`，否则会变灰、看起来卡顿。
- 投票 / 抽奖的作者侧是真实写操作：抽奖会托管萌萌点奖池与兑换码，开奖不可撤销。
  自动化只验证请求构造与模型解析，不调用真实接口；必须由驾驶员用测试话题验证。
- 抽奖编辑时，未改动的过去截止时间不能被表单拦下，只有真正修改日期时才校验「必须晚于现在」。
- 奖品图片的 `include_nsfw` 跟随内容姿态；隐藏模式只显示「N 张图片已隐藏」，
  模糊模式在缩略图上打码，不能绕过内容分级。
