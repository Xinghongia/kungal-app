# 2026-10-18 · 改名页萌萌点显示修正 + P0 投票/抽奖作者侧（0.8.19）

## 背景

驾驶员报告：资料设置里修改昵称时显示的「萌萌点」与真实余额不一致
（实际 56，界面显示 17）。同批要求补齐接口缺口清单的 P0：
话题作者在话题详情创建、编辑、删除投票与抽奖，并管理开奖与履约。

## 改名页萌萌点

- 根因：`/account-prices` 的 `rename_cost` 是**改名价格**（当时 17），
  界面把它拼成了「改名会消耗萌萌点（当前 17）」，读起来像当前余额。
  真实余额来自 `/me` 的 `moemoepoint`，之前虽然已经请求，但没有展示。
- 修正：文案改为网站同款「改名需要 17 个萌萌点。当前昵称：…」，
  并单独显示「余额 56 萌萌点」「改名花费 17」两个胶囊；
  确认弹窗显示「当前余额 X，改名后剩余 Y」。
- 改名成功后再拉一次 `/me`，余额立即变成扣款后的值。

## P0 · core 接口

`TopicApi` 新增：

- `updatePoll` / `deletePoll`：`PATCH|DELETE /polls/{poll_id}`；
- `createLottery`：`POST /topics/{topic_id}/lotteries`（幂等键）；
- `updateLottery` / `deleteLottery`：`PATCH|DELETE /lotteries/{lottery_id}`；
- `lotteryWinner`：`GET /lotteries/{lottery_id}/winners/{winner_id}`；
- `updateLotteryWinner`：`PATCH /lotteries/{lottery_id}/winners/{winner_id}`。

模型新增 `PollPatch`（含 `option_changes`）、`LotteryCreate`、`LotteryPatch`、
`LotteryPrizeInput`、`LotteryWinnerPatch`。`closes_at` 用 `JsonElement` 表示，
编辑时可用 `JsonNull` 明确清除截止时间（`KungalJson` 的 `explicitNulls=false`
会省略普通 null 字段）。

抽奖奖品图片模型修正为 `LotteryPrizeImage`：保留 `hash`、嵌套的 `image`、
`is_marked_adult`、`is_graded_explicit`。以前直接按 `ImageInfo` 解析，拿不到真实 URL
和成人标记，编辑表单无法原样回写。

## P0 · app

- 话题详情底部新增「话题小程序」面板，仅作者或有权管理话题的人可见；
  两张入口卡：投票 / 抽奖。
- 投票卡片按 `viewer.can_edit / can_delete` 显示编辑与删除；
  表单支持标题、描述、2–20 个选项、单选/多选、多选上下限、截止日期、
  结果可见性、匿名、允许改票。编辑时按网页规则只发 `option_changes`。
- 抽奖卡片按 `viewer.can_draw / can_edit / can_cancel / can_delete` 显示操作；
  删除、开奖、取消都有二次确认，文案与网页一致。
- 抽奖表单支持参与方式（报名 / 回帖 / 楼层）、开奖方式（到点 / 手动 / 满员）、
  楼层规则、开奖日期、注册天数与萌萌点门槛、公开参与名单、最多 10 个奖项；
  奖项支持名称、描述、名额、线下 / 兑换码 / 萌萌点三种发放方式、
  兑换码逐行填写、固定 / 均分 / 拼手气奖池、最多 9 张图片与 R18 标记。
- 已有人参与后，参与方式、楼层规则和奖项按服务端规则锁定；
  编辑奖项会整体重写并清空托管兑换码，表单会明确提示。
- 中奖名单按奖项分组，显示楼层、萌萌点与履约状态；作者可对线下奖品切换
  待发放 / 已发出 / 已确认收到 / 已放弃；中奖者本人可确认收到或放弃。
- 奖品图片按内容分级显示：隐藏模式不渲染、模糊模式打码、显示模式原图；
  抽奖列表的 `include_nsfw` 随内容姿态变化重新拉取。
