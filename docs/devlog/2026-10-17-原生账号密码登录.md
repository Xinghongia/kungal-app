# 2026-10-17 · 原生账号密码登录与注册（0.6.1）

## 背景

驾驶员提出：账号中心网页登录很简单（账号 + 密码，无滑块），注册也不复杂，
希望 App 不再一进登录就嵌整个网页。

## 登录链路（与网页同一套 OAuth，只读探测 + 前端契约）

1. `POST https://account.nextmoe.com/api/v1/auth/login`
   body `{account, password}` → `{code:0, data:{access_token, user}}`；
   错误示例：HTTP 401 `{code:10005, message:"用户不存在"}`。无验证码 / 滑块。
2. 生成 PKCE（verifier + S256 challenge + state）。
3. `POST https://account.nextmoe.com/api/v1/oauth/authorize/consent`
   （`Authorization: Bearer <access_token>`）body 为网页同款
   `client_id / redirect_uri / response_type / scope / state / code_challenge /
   code_challenge_method`；论坛客户端 `auto_consent=true`，直接返回
   `data.redirect_url`（含 `code` 与 `state`）。
4. 校验 state 后 `POST https://www.kungal.com/api/auth/oauth/callback`
   body `{code, code_verifier}` → 响应 `Set-Cookie: kungal_session=...`，
   App 捕获该 cookie 作为后续所有 API 的会话。
5. 注册：`POST /auth/register/send-code` `{name, email}` 发送邮箱验证码 →
   `POST /auth/register` `{name, email, password, code}` 返回 access_token，
   之后同样走 2–4。

使用的 OAuth client_id 是**网站前端公开的** `4ed9bc99ec0a789a4796b83e22bd84c5`
（`/oauth/client-info` 返回`鲲 Galgame 论坛`、`auto_consent:true`、`third_party:true`），
不是官方 App 的 Bearer client_id，不冒用官方 App 身份。所有请求只打官方接口，
不绕过任何门禁；与网页登录得到的是同一种会话。

2026-10-17 只读探测证据：`GET /oauth/client-info` 200；
`POST /auth/login`（假账号）401「用户不存在」；
`POST /oauth/authorize/consent`（假 token）401「令牌已过期」；
`POST /api/auth/oauth/callback`（假 code）400「无效的授权码」——四条路径均存在。

## 实现

- core：`AccountAuthApi`（登录 / 发送注册验证码 / 注册 / 授权同意 / 论坛回调），
  `Pkce`（RFC 7636），带内存 CookieJar（账号中心下发的 `nm_browser` 等）；
  业务码非 0 统一抛 `AccountApiException`，原样展示服务端中文提示。
- app：登录页重做为原生表单：
  - 「账号密码登录」：账号（邮箱或用户名）+ 密码，密码可见性切换；
  - 「注册新账号」：用户名、邮箱、验证码（60 秒重发倒计时）、密码、确认密码；
  - 用户名 / 邮箱 / 密码 / 验证码规则与账号中心网页一致；
  - 错误就地显示，不自动重试；登录成功后清空内存中的密码。
  - 保留「改用网页登录 / 注册」兜底（原 WebView 方案不变），
    遇到需要额外验证的账号时仍可走网页。
- 安全：密码只在内存，不写 DataStore、不写日志、不拼进任何 URL；
  README 仍为非官方第三方客户端。

## 未验证与已知边界

- **真实账号登录 / 注册未在驾驶员账号执行**：按约定写操作（登录、发验证码、注册）
  需驾驶员本人操作。请先在 App 里用账号密码登录一次；若失败，界面有「改用网页登录」。
- 注册会向邮箱发送真实验证码；未实测邮箱到达与验证码有效期。
- 账号中心接口不在论坛 OpenAPI 内，契约来自账号中心公开前端与只读探测；
  站点改版可能失效，届时回退网页登录并重新抓契约。
- 需要额外验证 / 二次认证的账号可能返回 `stepup_required` 等错误，App 会提示改用网页登录。
- 注册过程中账号中心下发的 cookie 只保存在内存；若发送验证码后杀掉 App 再重开，
  可能需要重新获取验证码（未验证服务端是否绑定该 cookie）。
